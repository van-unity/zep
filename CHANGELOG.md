# Changelog

All notable changes to Zep are documented in this file.

The package follows semantic versioning. Versions below `1.0.0` are previews and may include breaking API or workflow changes.

## [Unreleased]

### Changed

- **Breaking:** the package is now called Zep. The package id is `com.van-unity.zep`, the namespaces and assemblies are `Zep.*`, the window opens from **Window > Zep** with the tab title **Assets**, and the maintenance commands moved to **Tools > Zep**. Settings, tags, favorites, preferences and caches are stored under Zep names; data saved under the previous name is not migrated.
- **Breaking:** the one-time import of tags that the earliest version stored as Unity asset labels is removed. A project without a tag assignment file now starts with no assignments.
- **Breaking:** the built-in themes are reduced to four: Unity (Dark), Unity (Light), Zep (Dark) and Zep (Light). The Zep themes are the defaults. A saved preference for a removed theme falls back to the default.

### Added

- Several sidebar folders can be selected at once. **Cmd/Ctrl-click** adds a folder to the selection or takes it out, **Shift-click** selects every folder row from the selected one to the clicked one, and the asset area lists the contents of all selected folders together. A plain click, the arrow keys, a search or a tag go back to one folder.
- Any Assets/Packages folder or tag can become its own Unity window. Drag a sidebar folder, favorite or tag, or a single folder from the list or grid, outside the Zep windows: Unity's docking preview shows where it will land as a tab, a split or a floating window. Inside the panel the same drag keeps its existing meaning (move, favorite, split). Each window browses, selects, previews and edits on its own, follows the panel's theme, takes keyboard input as soon as it opens, and is restored after a domain reload or a layout change; it closes itself when its folder or tag is deleted. Because a single folder dragged out of the list or grid becomes a window, it cannot be dropped onto other editor windows such as the Inspector. Docking uses Unity editor internals; where they are unavailable, the drag falls back to an ordinary drag and logs one Console warning.
- Quick Finder resizes like a window: drag any edge or corner (the bottom-right grip stays as the visible handle), the size is remembered for the next open, and the popup opens centred on its host and is kept on that monitor, including after a drag that would carry it off. Its layout degrades by width and height separately: below 520px wide the named type chips collapse to All and Types… and result rows drop the type column; below 440px tall the context line and footer hints go, so the results keep the space. Results use the full available area, and the selected result stays visible while resizing. The type selector slides in from the right with searchable grouped rows, checkmarks, a selected count, and Clear/Done controls; it uses the available width in compact windows.
- Space on a search result now opens the asset browser's shared Quick Look, replacing the inline preview and its Show/Hide controls. Quick Look follows search selection; closing it returns focus to the result. Space continues to type normally in search fields.
- Quick Finder now offers recognizable asset rows, common and searchable type filters, removable restriction chips, shared Quick Look previews, recent queries, and no-match recovery. Search remains independent of browsing and exposes all matches through a virtualized list, with exact and prefix name matches ranked first. Single click highlights; double-click selects the asset in the main window, including folders in their parent. The Open/Reveal buttons and Enter activation have been removed. Typo suggestions respect explicit filters.

- Added Unity-familiar search syntax for types, Unity labels, project tags, names, paths, directories, extensions, asset areas, GUIDs, and glob patterns, including quoted phrases, exclusions, and exact matching.
- Added common type-kind filters for prefabs, models, folders, files, and objects.
- Added **Cmd/Ctrl+F** and the macOS Find command to focus the search field.
- Added a persistent horizontal split view for Assets/Packages folders and tags, with independent pane navigation, search, filters, selection, and list/grid presentation.
- Added dedicated Back/Forward controls and a root-clamped breadcrumb to folder split panes.
- Added collision-safe sidebar drag gestures, active-pane command routing, rooted-folder confinement, deterministic focus/replacement/close behavior, and read-only Tag destinations.
- Added mouse and keyboard divider resizing, accessible close controls, responsive pane chrome, and interruptible open, replace, close, preview, and focus motion.
- Added the Finder disclosure keys to sub-assets in list view. A row shows one chevron for both kinds of expansion, so the arrows now read the same on either: **→** opens a closed sub-asset disclosure and, pressed again, steps onto its first sub-asset; **←** closes an open one, and on a sub-asset row steps out to the row that owns it. Rows with no sub-assets, folder rows, and multi-selections are untouched, so folder expansion and **←** walk-to-the-parent-row behave exactly as before.
- Added typo-tolerant search suggestions. Typing a single plain term now offers up to eight name completions under the field, ranked by how closely they match and tolerant of small typos (`plyaer` still suggests `Player`). Down/Up move through the list, Enter or Tab accepts, Escape dismisses it. Suggestions respect the pane's folder scope and type filter, and an accepted completion is quoted when the raw name would otherwise parse as a different kind of query.

### Changed

- The panel's icons are now drawn from [Phosphor Icons](https://phosphoricons.com) (MIT), replacing the previous glyph set. Sizes, positions and theme tinting are unchanged; the shapes differ slightly. Attribution is in `Third Party Notices.md`.
- Softened the Inspector ping in the assets list and grid. The two thick rings and the scale punch of the row or tile are gone; a ping is now one thin ring in the selection accent that holds for a beat and fades while growing barely a percent.
- Reworked the list view's detail columns. Tags on a list row are now bare colour dots, Finder-style, with the tag names in the row's tooltip, instead of labelled pills; they sit in their own slot between the name and the date, standing clear of the Date Modified column instead of touching it; the Date Modified, Size, Type and Addressable cells keep a 16px gap between them and start exactly under their headers (the header also accounts for the list's scrollbar, so the columns stay aligned once it appears); a folder shows **—** in the Size column rather than an empty cell; and the Addressable column is only rendered when the Addressables package is installed.
- The sidebar highlight now follows where a navigation came from. Clicking a favorite lights the favorite row only: the Assets and Packages trees no longer select, expand to, or scroll to that folder. A tree click, the favorite's **Reveal in Tree**, or navigating anywhere else hands the highlight back to the trees. Dragging a favorite into the workspace opens it in a split view exactly as dragging a tree folder does (dropping it back on the list still reorders). Favorite rows take the keyboard: **Up/Down/Home/End** walk the favorites, **Enter** opens the focused one, the context-menu key shows its menu, and **Delete** is refused with the system beep, as in Finder: a favorite leaves the list only through **Remove from Favorites**. An empty section shows a **Drag folders here** hint, and the Favorites and Tags folds are remembered across domain reloads. Favorites moved from the version-controlled `ProjectSettings/` to the per-user `UserSettings/`; the first open with no per-user file imports the paths from the old project file, which is left in place for the project owner to delete.
- Slimmed the stylesheet after the 2026-09-03 USS audit: `Zep.uss` drops from 4,164 to about 3,370 lines with the same layout, and the theme vocabulary from 47 to 39 tokens. Chrome-less buttons now share one `zep-flat-button` primitive, pinned sidebar rows one `zep-sidebar-row` rule, breadcrumbs one base rule, and every drag-over surface one `zep-drop-target` state class. Six never-bound "reserved" tokens, the folder-icon tint token (always equal to the icon tint) and the press-state token `--zep-bg-item-selected` were removed; saved user themes keep loading. Hover and press fills on the panel's buttons and list rows are now painted from the theme in every state: the editor skin's grey hover and blue press had been winning on specificity for flat buttons, action buttons, breadcrumb segments and the sidebar folder tree. Press feedback on the split-pane controls and breadcrumb segments uses the secondary-active fill, and the Quick Look filmstrip's selected tile uses the shared selection accent.
- Reworked catalog ownership, folder browsing, search publication, creation fallbacks, startup hydration, and external import so ordinary local changes publish path-scoped deltas instead of rebuilding the full project projection. Direct folder observation now makes first browse independent of global search readiness, while explicit Refresh remains the authoritative recovery path.
- The minimum supported Unity version is now Unity 6.0 (6000.0). Every Unity 2022 compatibility path is removed: the pre-6000 `PreventDefault` event suppression, the `PhysicMaterial` type alias, and the legacy undo-group marker machinery (with its persisted session payload) that worked around 2022 keeping empty native undo groups.
- The GitHub EditMode matrix now targets Unity 6.0 LTS, Unity 6.3 LTS, and Unity 6.5.
- Object identity now flows through `EntityId` on Unity 6.5+, where the instance-id APIs are compile errors: the undo cursor persists via `SessionState` EntityId storage, undo change events compare `entityId`, sub-asset resolution and preview polling use `GetEntityId`/`EntityIdToObject`, all behind version gates that leave 6.0–6.4 unchanged.
- Plain search terms now combine with AND; repeated type filters combine with OR, repeated Unity-label filters combine with OR, and the resulting type and label groups combine with AND.
- `l:`/`label:` now searches real Unity asset labels, while `tag:` remains dedicated to Zep project tags.
- Every theme now paints the selection highlight at the same opacity. The fill is a translucent tint of the theme's own accent colour instead of, depending on the theme, an opaque bar or a barely-there wash, so a selected row reads with the same strength whichever theme is active.
- Grid tiles and list rows now share one selection colour. Grid selection had its own theme tokens (`--zep-bg-grid-item-selected`, `--zep-border-grid-item-selected`) that had drifted from the row tokens, so switching between list and grid changed how a selection looked; both tokens are removed and every selectable surface binds `--zep-bg-item-selected-accent` / `--zep-border-item-selected-accent`. Custom theme assets keep loading — the removed entries are ignored, and grid selection picks up the shared colour they already store.
- The bottom bar (view toggle, thumbnail slider, breadcrumb, file count) now occupies its own row instead of floating over the assets. It used to be pinned over the bottom of the asset area, so rows scrolled underneath it and each view compensated with 44 px of empty padding; the asset list and grid now simply end where the bar begins.
- Reworked how the grid shows sub-assets. Expanding a parent tile now flows its children into the tile stream directly after it — wrapping onto the following rows when they do not fit, with a tinted group background, segment notches at both ends, and a continuation marker on wrapped rows — instead of the old per-tile chip and meta line. The grid still virtualizes fixed-height rows and counts assets without materializing them, so a folder with a million entries realizes only what the viewport shows.
- Removed the unused `--zep-bg-grid-item` / `--zep-border-grid-item` theme tokens (schema is now 47 tokens). The grid tile base has been transparent since the grid rework, so every theme was hand-tuning a colour nothing read; custom theme assets keep loading and the removed entries are ignored.
- Search suggestions compute one bounded edit-distance table per candidate instead of one per prefix length — about three times less work per keystroke on the typo-tolerant pass, with identical suggestions (verified on a randomized corpus).
- Script-type reconciliation after a script reload is now budgeted at 2 ms per frame and continues across ticks instead of rebuilding every ambiguously typed record in one main-thread pass.
- An unqualified search term now matches a GUID only as a prefix of at least four characters, and a `guid:` fragment resolves against the first eight characters of a GUID — a longer fragment must be a prefix, and a full 32-character GUID still matches. Two or three plain letters used to be tested as a substring of every GUID in the project, which surfaced results nobody was looking for and made the index carry postings for all 32 characters of every GUID.
- A `glob:` pattern with no run of three or more literal characters between its wildcards (for example `glob:"**/*a*"`) is now rejected as too broad and matches nothing, instead of falling back to a scan of every path in the project.
- The search field raises one query per editor tick instead of one per keystroke. Characters typed inside the same tick supersede each other, so typing a word no longer runs the whole pipeline — parse, candidate resolution, projection — once for every prefix of it. Clearing the field with Escape or the ✕, and accepting a suggestion, still take effect in the same event.
- The global search index is warmed at startup only in projects where the panel's search has been used before; the observation is stored in `EditorPrefs`, keyed by project path. A project that has never been searched no longer pays a background index build on every editor start, and the first search there builds the index on demand exactly as it already did on a cold panel.
- The undo history keeps at most 200 records. Past that the oldest record is dropped, and the revision arithmetic that pairs the panel's stack with Unity's native undo steps now runs against a persisted trim base, so a trimmed session still replays the right command for each native step.
- The warm search index is about 44% smaller at 100,000 assets (259 MB to 145 MB; 2,716 to 1,523 bytes per record): GUIDs no longer contribute to the any-field text, their gram postings cover only the first eight characters, and the one- and two-character type postings are replaced by a lookup keyed on each record's whole type text. The trade is that a one- or two-character `t:` matching more than one type now merges candidate lists, costing a few milliseconds on that keystroke.
- A broad search run straight after an import or rename no longer re-sorts the whole result set; the ordinals a delta appends are merged into the existing alphabetical order in one pass. On a 100,000-asset corpus the first query after a one-record edit went from 36 ms to 1.2 ms.
- Rebuilding tag presentation no longer reads a `.meta` file per asset — the GUID already on the indexed record is used for the lookup — and a tag-definition edit re-resolves only the paths that actually carry an assignment, publishing one catalog delta for the whole sweep instead of one per record.
- A bulk delete issues one global `AssetDatabase.Refresh` for the whole batch instead of one per item, saves the undo history once per native undo step instead of once per command, and deleting several sidebar folders now runs as a single batch instead of one catalog update, projection, and refresh per folder.
- Restoring a deep sidebar expansion is bucketed by parent folder instead of scanning the whole folder catalog per row. On a 10,001-folder fixture with 2,001 folders expanded, the first apply went from 2,098 ms to 36 ms.
- The persistent index snapshot is serialized on a worker thread and committed on the main thread a frame later, so writing a large project's snapshot no longer blocks the editor. Every abort leg of the save keeps its previous meaning, and the synchronous save that a blocking **Refresh** relies on is unchanged.
- Reworked how the assets grid shows sub-assets. A selected or hovered tile now paints a card that hugs its thumbnail and name instead of filling the whole row-cell, so a selected tile no longer carries a blank slab under its name at larger thumbnail sizes. An expanded asset and its sub-assets sit together in one outlined group container that starts at the parent (it used to start beside it and overlap the parent's selection), wraps onto following rows with a notch, and keeps the names inside it; selecting a sub-asset highlights its own card. Grid rows are now pitched to the tile content at every thumbnail size, which removes the wasted space under tiles at the largest size and the overflow at the smallest. The column count also stopped charging a trailing gap for the last column, so a row that has room for one more tile no longer wraps it and leaves a tile-wide hole at its end.

### Removed

- Removed the Recents feature: the sidebar Recents row, the Recents assets view, and Recents as a split-view source. Opening an asset no longer records it, and the `ProjectSettings/Zep.Recents.json` store is no longer read or written — delete it if it exists. Restored split layouts that named Recents drop that pane; other panes restore unchanged.
- Removed the two leftover empty `Samples~` directories and the zero-byte `GEMINI.md` from the package. The 0.2.1 entry below already announced the empty sample; the folders had stayed behind.

### Fixed

- Installing the package from a Git URL no longer logs two "A meta data file (.meta) exists but its folder ... can't be found" warnings. The repository carried `.meta` files for two empty folders, which Git does not store.
- Importing the package no longer logs "not generated because the rect lies (partially) outside of texture" warnings for its icon textures. Thirteen icons were still imported as multi-sprite sheets with rectangles from much larger original images; they are now single sprites.
- Fixed **Replace** in the Move Conflict dialog never replacing anything: the move was refused with "already exists" over the item it had just moved aside. Unity's asset database is frozen while a drop is processed, so it kept reporting the displaced item; presence is now answered from the disk during a drop. Undoing and redoing a Replace keeps both items' GUIDs (tags and references).
- Fixed **Keep Both** failing with Unity's raw "Destination path name does already exist" when another item of the same drop had just taken the copy name it chose.
- Fixed **Create > Scene** failing with "Cannot create a new scene additively with an untitled scene unsaved" until a scene had been saved once in the session. The scene file is now written the way Unity's own Create > Scene writes it, without touching the open scenes.
- Fixed creating a script from the panel discarding the panel's whole undo history and leaving the new script impossible to undo (Console: "…did not provide a stable identity for Undo"). The script import starts a compile, and the undo record was refused while Unity compiled.
- Fixed **Escape** not cancelling a marquee selection in the main window: the rubber band kept tracking and selected on release. It now restores the selection from before the drag, as it already did in a pane window.
- Fixed `Invalid editor window of type: …` being logged every time a window was maximized. The panel's Inspector-ping receiver was a hidden, never-docked window, and Unity's maximize reports every such window. On Unity 6.3 and later the hidden window is gone: the panel window itself now receives pings, through a small editor-only assembly named `Unity.InternalAPIEditorBridge.024` (the name Unity reserves for reaching its internals). On 6.0–6.2 pings still need a hidden Project Browser; it is now titled `Zep.PingReceiver` and its maximize error is filtered out, while a real Project window's error is still reported.
- Reloads no longer rebuild the index on uncertainty. The index cache is loaded whenever it can be read; the changes Unity reported since it was written are replayed from the change journal, and anything the journal cannot vouch for — an interrupted journal write, a tag edit, a change the journal could not describe, or the first open of an editor session — is reconciled by a silent background walk that applies only the difference. The **Building project index** overlay now appears only when there is no cache at all. The filesystem-timestamp signature that used to decide whether the cache was trustworthy is gone, and the journal is kept as one file per recorded batch, so a change arriving while the cache is being saved can never be lost or contended. **The first open after this change rebuilds the index cache once, behind the usual scan overlay**, because the cache format changed (version 12); opens after that are normal.
- Fixed the panel rebuilding its whole index behind a **Building project index** overlay after a script was created, saved, or deleted under `Assets/`, and fixed it coming back on the `Assets` folder instead of the one that was open. Three causes, each pinned by a test that performs a real domain reload headlessly (`ScriptChangeReloadScenarioTests`: create, Rider-style safe-write edit, delete, folder-then-script): the pending-change journal refused to replay a folder created before the reload (it now reads the folder's subtree through the browser's own folder observer); the retype job that follows a compile marked the cache "dirty" when Unity's second import pass of the script moved the journal under it, so the *next* reload distrusted a complete snapshot (a save that touches nothing on disk no longer marks anything; only a cold scan's save does); and Unity restores the window's plain private fields across a reload, so the one-shot restore latch and the open-window registration came back already set (both are cleared when the window is disabled, so the saved folder is re-applied and Inspector ping reveal keeps working after a reload). A fourth cause showed only on a real-sized project: a newly created script gets a second import pass after compilation, and on a large project that batch lands while the reload is still reading the snapshot on a worker, which used to make the snapshot "not current" and rebuild; a journal that only grew during the read is now replayed in full instead. Perf logging now names every cold scan's reason (`cold-scan reason=…`) and counts overlays (`ColdScanOverlays`).
- Fixed the selected asset being deselected after a script compile: Unity keeps its selection across the domain reload, and the panel now mirrors it back into the restored folder once the window is rebuilt, so the script being edited stays highlighted as it does in Unity's own Project window.
- Fixed a deleted script coming back as a row nothing on disk backed when it had been created, renamed and deleted before its compile's reload: the journal compacts the rename and the delete into one batch, and the replay re-added the renamed asset after removing it. A rename whose target the same batch deletes now only removes the source.
- Fixed a script created under a default name and renamed before its compile finished (Unity's own Create item run through the panel, or a create accepted as `NewMonoBehaviourScript` and renamed) rebuilding the index behind the overlay on the reload: the journal's import of the since-renamed path is now recognised as gone from its folder and skipped, and the rename that follows it replays normally.
- Fixed a script created from the panel's own Create menu rebuilding the index after its compile: the ping reveal for a just-created asset used to give up after three editor frames and force a full rebuild while the panel was still loading its snapshot. It now waits for the panel to finish loading and never forces a rebuild.
- Fixed **Create > MonoBehaviour Script** from the panel's menu running Unity's own menu item instead of the panel's named create: Unity 6 lists that item at the top of the Create menu as well as under Scripting, and only the Scripting path was known to the panel, so the top-level one created `NewMonoBehaviourScript.cs` and renamed it after the import (which is also what made a second default-named script collide on its class name). Both menu paths now write the typed name directly.
- Fixed Back/Forward history being lost on every domain reload: the primary pane's history is now saved with the window alongside the current folder and re-applied after the reload, so Back still walks the folders browsed before it.
- Split panes keep their Back/Forward history across a domain reload as well: each split pane's history is saved with the split layout and re-applied when the pane is rebuilt, so a script edit, create, or delete no longer empties Back inside a split view.
- A domain reload no longer costs the panel its place, its folder icons, or a rescan of the project. Editing a script used to send the panel back to `Assets`: a domain reload restores the panel window's plain private fields as well as its serialized ones, so the window came back believing it had already attempted its one restore and never applied the folder it had saved — and the fallback it then painted was written back over that saved folder, so the next reload had nothing left to recover. Every folder then showed the empty-folder icon for the seconds that followed, because a folder the index had not read yet was treated as empty rather than as unknown. Underneath both, a compile escalated into a full filesystem walk that nothing announced — the walk descended into macOS plugin bundles, and the first path inside one, which Unity had never imported as an asset of its own, could not be rebuilt and turned the whole reload into a silent authoritative rescan. A reload is now a cache load: the folder and selection you had come back and stay, a folder shows the empty-folder icon only once the panel knows it has no children, and the types a compile actually changed are rebuilt a few per frame and appear as they land, without re-listing a folder or re-scanning the project. Directories Unity imports as a single asset (`.bundle`, `.framework`, `.xcframework`, `.plugin`) are indexed as one leaf asset each and are no longer descended into. **The first open after this change rebuilds the index cache once, behind the usual scan overlay**, because the cache format changed so that no record from inside a plugin bundle can survive in an older snapshot; opens after that are normal.
- The Addressable column and the grid's addressable badge now actually mark addressable assets. The package was located through reflection under the wrong namespace (`UnityEditor.AddressableAssets.Settings` instead of the package's `UnityEditor.AddressableAssets`), which read as "Addressables not installed" on every version, so no asset was ever marked. A folder entry now marks the folder itself as well as everything under it, and marking or unmarking an asset while the panel is open updates the column without a domain reload: the panel listens to the Addressables settings and re-reads the entry set, without rebuilding the search index.
- Selecting a sub-asset no longer loses the selection when the folder's contents are re-published. A selected sub-asset is painted by the row's own highlight — it has no asset path of its own to fall back on — and every asset push cleared that highlight, on the assumption that a new list always meant navigation. It does not: a folder under a type, tag, or search filter rebuilds its entries on every publish, and committing a sub-asset provokes a publish of its own. So pressing **↓** from an asset whose sub-assets were open selected the first sub-asset and then immediately un-painted it, leaving nothing selected at all. The highlight is now dropped only when the row it points at is genuinely gone. Both list and grid views.
- Clicking a row's expansion chevron no longer breaks the keyboard. The press opened the collection's deferred-selection window — the window that keeps a drag from retargeting the Inspector — but the chevron is a button that captures the pointer, so the release never returned to close it. Every selection change after that was buffered and dropped: arrow keys moved the highlight while the panel's own state, Unity's Selection, and the Inspector stayed behind, so **↓** on an asset whose sub-assets had just been expanded appeared to do nothing, and **→** could not expand a subfolder reached by walking into a folder opened by its chevron. The chevron press now leaves that window alone, as its click-owning guard always intended.
- Arrow keys now walk expanded sub-assets. With a sub-asset selected, navigation used to read the (deliberately empty) path selection as "nothing selected" and jump to the first or last main asset in the folder; from a main asset it skipped an open expansion entirely. The keyboard cursor now steps through the visible order — rows and tiles alike, sub-assets included — so ↑/↓ (list) and the arrows (grid) move between siblings and step out at the parent, and a **Shift** range, which is keyed on asset paths, still spans main assets only. In list view **←** on a sub-asset row also steps straight out to the row that owns it, however deep into the children the cursor sits.
- Selecting or hovering an expanded sub-asset in grid view now highlights that entry's slice of the shared group strip instead of filling its whole tile. The tile is a full row-cell, taller than the strip and name it shows, so the old root-level fill drew an oversized accent (or hover-grey) slab over the group; the accent now lives on the strip segment, matching how the strip itself is painted.
- Grid rows now re-pitch when the thumbnail size changes. Unity's fixed-height virtualization keeps already-realized rows at their old height when only `fixedItemHeight` changes, so after zooming in, every tile silently overflowed its row and a selected tile's highlight rectangle painted across the entries below it. The grid now rebuilds its rows on a size change, exactly as the list view already did.
- **Cmd+Delete** (macOS) / **Delete** (Windows/Linux) now deletes the selected sidebar folder when the sidebar folder tree has keyboard focus, with the same confirmation the folder's context-menu Delete shows. The chord previously only ever targeted the asset-area selection, so with focus in the sidebar it silently did nothing. Focus anywhere else keeps the existing behavior: the chord acts on the asset selection and an empty selection stays a no-op.
- Warm project opens and script recompiles no longer show the full project-index build overlay. Domain-reload callbacks and pathless `projectChanged` signals preserve the snapshot before panel hydration, while artifact-only changes reconcile metadata without the cold-build UI.
- An empty folder now shows the same striped list surface a populated one does. The list view was hidden outright when a folder had no assets, so the Finder-style alternating bands stopped at the folder boundary and left a blank slab.
- The selected folder in the sidebar tree now carries the same accent fill and border an asset row does. It previously showed only a bold label — its two selection rules were written against a per-item wrapper the folder list does not have, so one matched nothing and the other actively painted the row transparent.
- Cancelling a search after picking a result now scrolls the sidebar folder tree to the result's containing folder, so the selection is visible instead of landing off-screen (matching Unity's Project window). Keyboard tree navigation reuses the same framing and now survives multi-frame layout of freshly expanded branches.
- Prefab and model filters now remain distinct even when Unity reports both assets as `GameObject`.
- Concrete custom asset types (for example `t:EnemyConfig`) and their real CLR base types now survive background indexing and persistent-cache hydration; non-ScriptableObject files saved as `.asset` no longer produce false `t:ScriptableObject` matches.
- Unity labels and GUID filters now include folders, including incremental label edits and warm-cache startup.
- `**/` glob segments now match zero, one, or many folder levels, and literal glob candidates avoid full-project scans.
- Complete type-kind aliases match exact alias lines, so `t:script` no longer matches `ScriptableObject`; partial type text remains available while typing.
- Incremental imports and renames retain stable alphabetical result order without repeatedly sorting broad result sets.
- Persistent-cache validation now uses Unity's artifact dependency revision, avoiding cache-hit concrete-type scans while invalidating in-place `.meta` GUID changes.
- Background folder snapshots now come from the same enumeration as their assets, retain authoritative package-root metadata, and honor the native-source kill switch.
- Replacing a `.meta` file in place now atomically replaces the old GUID in both the asset index and an already-warm search index, preventing duplicate or ghost results.
- Tag-only refreshes now preserve concrete-type ancestry, so base-type queries remain correct immediately after tag edits.
- Cold background scans can no longer overwrite imports or deletions that arrive while enumeration is running, and incomplete scans caused by metadata read failures are discarded instead of cached.
- Deferred filesystem-signature enumeration failures now return an unknown signature and force a safe rebuild instead of escaping cache validation.
- Empty quoted qualifiers such as `t:""` no longer broaden to the whole project.
- Empty extension qualifiers such as `ext:.` no longer match extensionless assets.
- Search results shown in a rooted folder pane can no longer escape that pane's root.
- Search scope controls remain visible when a tag filter is active without search text.
- Cancelling a search you never picked a result in now leaves you where you are. It used to reopen the browser at whatever asset you had selected last — often a folder you had left long before typing — because the reveal targeted the last selection of the whole session instead of the result picked during that search.
- Case-only renames (for example `foo` → `Foo`) now apply on disk instead of silently keeping the old casing and recording a no-op undo step.
- Compact pane chrome no longer leaves a stray breadcrumb divider visible at narrow widths.
- Dropping files Unity does not import (dotfiles, `~` folders) no longer erases the undo history, and later files in the same drop keep their undo records.
- Deleting a selection that contains a folder together with its inline-expanded child now deletes every selected item instead of stopping on a false identity error.
- Multi-item drops report one aggregate status ("Moved 2 of 3 — 1 failed") instead of overwriting each failure with the next.
- Folders gaining or losing their first child through external changes now update their expansion chevrons immediately, and expanded-but-empty folders show newly added children without a manual refresh.
- A corrupt persistent-index row now falls back to a rebuild with a console warning instead of aborting cache hydration with an exception.
- Opening the panel no longer loads every labeled asset into memory to read its Unity labels.
- Flow-style `labels: [a, b]` lines in hand-edited `.meta` files are now indexed incrementally, matching what a full rebuild produces.
- A rename edit whose row is scrolled away, released by a shrinking list, or refreshed out of the data set now cancels cleanly instead of trapping the keyboard in an invisible field.
- The remembered search-scope preference survives visiting places where that scope does not apply, instead of being overwritten by the fallback.
- Corrupt or duplicate tag definitions are dropped with a warning on load instead of being silently rewritten and saved back with new identities.
- Grid keyboard navigation moves by on-screen tiles when sub-asset expansions are open, instead of drifting to non-adjacent tiles.
- Keys pressed immediately after dismissing a prompt are no longer swallowed during the close animation.
- The sidebar reveal scroll follows the target folder by identity when the tree changes mid-scroll, instead of framing whatever row slid into the captured position.
- Registry-package folder changes now refresh the view immediately instead of waiting for the next unrelated event.
- The drag cursor over sidebar folders no longer advertises a move onto rows where the drop would do nothing.
- Asset changes that happen while the index is not listening — during a domain reload, between editor sessions, or while a background scan is running — are now recorded in a durable journal that survives restarts and replays in the order they occurred. A journal that was interrupted mid-write, contended by a second editor, or grown past its bound is rejected outright and the following scan is treated as authoritative, so a partial history can never be trusted as a complete one.
- The persistent index cache is now bound to the recovery epoch it was written in, and cache saves are serialized against Unity's own asset callbacks. A cache written across an interrupted session, or while imports were still arriving, is discarded instead of hydrating a project state that never existed. Scan overlays and cache overlays are kept separate, so an in-session change can no longer be mistaken for cached truth.
- Only one background scan owns the index at a time, and every piece of deferred work is bound to the run that started it, so a superseded scan can no longer publish over a newer one. A manual **Refresh** adopts the scan already in flight instead of racing a second one, and a refresh whose scan faults is retired — the panel returns to a usable state instead of waiting on an operation that will never finish.
- Script recompiles reconcile only the metadata that actually changed instead of forcing a cold rebuild, imports that were still unresolved when a scan started survive it, and directory signatures are computed in a stable order so an unchanged project keeps producing the same signature.
- An inline rename now survives a list refresh on Unity 6.5, where the row is released and re-bound inside a single pass. The edit is cancelled only when its row is genuinely gone.
- Creating a C# script from a name that is not a valid identifier now produces a file that compiles: `My Player.cs` declares `MyPlayer`, `3Dee.cs` declares `_3Dee`, and non-ASCII letters survive unchanged. The first version of this fix stamped the raw file name into the type declaration, so a space, a dot, or a leading digit produced code that did not compile, and on the menu-item fallback path it could corrupt a type name that was already valid. A name that reduces to nothing usable, or to a C# keyword (`class.cs`), now keeps the template's own type name — a file-name/type mismatch compiles, invalid C# does not.
- A corrupt `ProjectSettings/Zep.TagAssignments.json` (a merge conflict, most likely) no longer empties your tags and then overwrites the file with the empty result on the next tag edit. The parse now happens into a scratch map that is only adopted when it succeeds, the panel reports the file path and leaves the file alone, and tag saves are refused until a corrected file loads cleanly.
- An exception thrown inside any deferred editor callback no longer wedges the panel's deferred work for the rest of the session. The panel now drains its own queue and isolates each callback, so index refresh, external-change projection, and the deferred search build keep running (the failure is logged and attributed) instead of silently stopping until the next domain reload. Cancelling a deferred callback is also authoritative while the queue is draining.
- Search suggestions no longer drop the best completion. The candidate scan used to stop as soon as the list was full, so an exact short name that sorted after eight longer prefix matches (`Players` behind `PlayerAbilityAController`…) was never considered.
- Accepting a suggestion whose name is 32 hexadecimal characters now finds the asset instead of nothing: the completion is quoted so it is not re-parsed as a GUID query. Names with leading or trailing spaces round-trip too.
- A rename started on a grid tile that then falls out of range — because the folder shrank or the panel got narrower — is now released instead of leaving an invisible focused text field that swallowed every keystroke.
- The list view's "Sub-asset" chip is now actually visible, and pooled rows no longer accumulate a hidden label per bind.
- A marquee drag in the grid now selects the row it grazes: the row math measured from the list instead of its content viewport and so ignored the list's 4 px padding, resolving bands one row low near a boundary. The sub-asset strip is also aligned correctly on a tile's very first bind, instead of only after it is rebound.
- A sub-asset ping whose target never arrives no longer leaves its parent pinned open as an empty expansion.
- Quick Look opened while nothing is selected now follows the selection that arrives afterwards, instead of staying on "Select something…" until it is reopened.
- The status toast fades again. The window's entrance animation left an inline opacity on the status bar that outranked the toast's own transition for the lifetime of the window, so toasts could only pop in and out.
- A custom theme now survives a scene load (its generated stylesheet is flagged to outlive one), and closing or reloading the window releases that stylesheet instead of orphaning one per domain reload.
- Package folders keep their manifest display names after an incremental update. A change under `Packages` used to rebuild that listing from raw package ids, which both showed the wrong text in the wrong order and broke ping/reveal into a package root.
- A deferred background worker that faults is now reported and retried once instead of being swallowed, so search postings and the Addressables badge are no longer silently stale for the rest of the session.
- External file drops classify paths against the project root Unity reports rather than the process working directory, which the two drop paths disagreed about whenever anything changed the working directory.
- The in-session scan overlay coalesces repeated changes to the same asset and is bounded; past the bound it is dropped whole and the next scan is treated as authoritative, instead of growing for the length of the session.
- Renaming to a name that contains `/` or `\`, to `.` or `..`, to a Windows reserved device name (`CON`, `nul.txt`, `COM1`, `LPT9`), or to a name ending in a dot is now refused with one message and no undo entry. `sub/child` used to be taken as a path: the panel silently created a `sub` folder and moved the asset into it. `Console` and `COM10` still rename normally.
- Deleting or duplicating several items now continues past an item that fails and reports the aggregate ("Deleted 4 of 5 — 1 failed; first: This item is read-only."). The loop used to stop at the first failure, leaving the rest of the selection untouched and showing only that one item's error.
- An external change batch containing a path the index cannot resolve now applies the part it can and reconciles the rest in the background, instead of discarding the whole batch and waiting for a full recovery pass.
